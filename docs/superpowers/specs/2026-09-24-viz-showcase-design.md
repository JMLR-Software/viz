# viz.jmlr.dev — data-visualisation showcase design spec

**Date:** 2026-09-24
**Status:** design approved in conversation section by section, 2026-09-24; this written spec awaits Josh's review
**Supersedes:** nothing. `2026-09-13-allstar-shots-design.md` stays the contract for the shots showcase itself; this spec covers the shell around it and the new showcases.

## 1. What it is

A small gallery of D3 data visualisations at `https://viz.jmlr.dev`. A dropdown in the header switches between showcases; each is a page of its own with a one-line hook. The first showcase is the existing All-Star Shots dashboard. The others are a US tornado heat map, an earthquake globe, US flight arcs, and an NBA all-time scoring bar chart race.

**Who it is for:** reels. Each showcase has to read in a phone recording, carry a hook in its first second, and move on its own. Being useful comes second to being striking, but every number is still real (§3).

**Not a revenue bet.** Must not compete with the Fantasy IQ season window (opens 2026-10-20). See §9 for what gets built before then.

## 2. Scope

| In | Out |
|---|---|
| Five showcases: shots, tornadoes, quakes, flights, scoring | User-uploaded data, a chart builder, embeds |
| A shared header with the dropdown, a `/` tile grid, record mode | Accounts, comments, sharing buttons |
| Real public data, fetched on a laptop and committed | Runtime calls to any outside API, live-updating data |
| A dark theme across every showcase | A light theme or theme toggle |
| `shots.jmlr.dev` redirecting to `viz.jmlr.dev/shots` | Keeping `shots.jmlr.dev` as a separate site |

## 3. Rules that change

- **Rule 1** widens from "the data is what the NBA reported" to **"the data is what the named public source reported."** No invented, smoothed, or imported-from-elsewhere values. `public/data/` is generated by the scripts under `scripts/` and never hand-edited.
- **Rule 2** becomes **"the Worker never calls an outside API."** The Worker serves files and does one host redirect (§5).
- **Rule 6** becomes **"every showcase footer credits its source and states no affiliation."**
- Rules 3–5 (pure tested math, constants in config, immutable data) apply to every showcase unchanged.

## 4. Repo and layout

The repo is renamed `allstar-shots` → `viz` (GitHub repo, local folder, Worker name). GitHub redirects the old URL.

```
src/web/shell/          header + dropdown, record mode, showcase registry, theme
src/web/<slug>/         one folder per showcase: index.ts (DOM) + lib/ (pure, tested)
src/worker.ts           host redirect, then static assets
public/index.html       the tile grid
public/<slug>/index.html
public/data/<slug>/     generated, committed
scripts/<slug>/         one fetch script + pytest + fixtures per showcase
```

Slugs: `shots`, `tornadoes`, `quakes`, `flights`, `scoring`.

**The registry** is one list in `src/web/shell/registry.ts` of `{ slug, title, hook, credit }`. The dropdown, the `/` grid, and the tests all read it. Adding a showcase is one registry entry plus its folders.

**Build.** esbuild takes one entry per slug plus the index, with `splitting: true`, so D3 and the shell are fetched once and cached across pages.

## 5. The shell

**Pages.** `/` is a grid of five tiles, each with its title and hook. Every showcase page carries the same header: the "viz" wordmark, a large dropdown, and the hook line. Choosing an option navigates to that page; cross-document View Transitions (`@view-transition { navigation: auto; }`) crossfade the change. Browsers without support simply navigate.

**Record mode** (`?rec` on any URL, carried through dropdown navigation):
- the page locks into a centred 9:16 frame with larger type;
- the dropdown stays visible, since switching showcases is part of the reel;
- the footer shrinks to the one-line credit;
- every animation autoplays and loops, and nothing depends on hover.

**Theme.** One dark theme, tokens on `:root`. Shots is restyled to it; its behaviour does not change.

**Redirect.** The Worker gets a `main` script: requests whose host is `shots.jmlr.dev` get a 301 to `https://viz.jmlr.dev/shots` plus the original path and query; everything else goes to the static assets. Both hostnames are custom domains on the one Worker.

**Reduced motion.** `prefers-reduced-motion: reduce` stops autoplay (showcases open paused on their final frame) except in record mode.

## 6. The showcases

Each has a fetch script, a pure `lib/`, and a canvas renderer (canvas rather than SVG, so tens of thousands of marks stay smooth in a recording). Each showcase's data is at most about 2 MB in total.

### 6.1 Shots (`/shots`) — existing

Moved from the root to `/shots` with its code under `src/web/shots/`. The 2026-09-13 spec still governs what it shows.

### 6.2 Tornadoes (`/tornadoes`) — "Every US tornado since 1950"

- **Source:** NOAA Storm Prediction Center severe weather database, tornado file for 1950–2024 (`spc.noaa.gov/wcm/data`): start and end coordinates, EF/F rating, state and county FIPS. County shapes from the `us-atlas` package (Albers USA, pre-projected).
- **Data written:** per-county per-year counts (sparse) and per-year track segments (start and end points, rating), in the same projection as the map.
- **What moves:** a timeline plays 1950→2024 in about 20 seconds. Counties heat up with their running total on a sequential scale. Each year's tracks flash as bright lines along their real paths, then fade into the heat.
- **Interaction:** scrub the year, an "EF3+ only" toggle, tap a county for its name and count.

### 6.3 Quakes (`/quakes`) — "Every M4.5+ earthquake in the last year"

- **Source:** USGS FDSN event API, magnitude ≥ 4.5, the 12 months before the fetch date (about 7,000 events). Land from `world-atlas` 110m.
- **What moves:** an orthographic globe rotates slowly while the year replays in time order; each quake appears as a ripple sized by magnitude.
- **Interaction:** drag to rotate, a minimum-magnitude slider.
- **Dated:** the hook and footer state the window ("Oct 2025 – Sep 2026"), since the data does not refresh itself.

### 6.4 Flights (`/flights`) — "Every US domestic route, by passengers"

- **Source:** BTS T-100 Domestic Segment (All Carriers), calendar year 2025. TranStats has no scriptable download, so Josh downloads one CSV by hand; the script reads that file from a path given on the command line. The README documents the download form's exact field choices. Airport coordinates from the BTS Master Coordinate table (also a manual download, documented alongside).
- **Data written:** the top 1,000 airport pairs by passengers (both directions summed), with passenger and departure totals.
- **What moves:** great-circle arcs on Albers USA, width by passengers; small dots travel along each arc at a rate tied to departures.
- **Interaction:** tap an airport to show only its routes; tap empty space to clear.

### 6.5 Scoring (`/scoring`) — "The NBA's all-time scoring list, season by season"

- **Source:** `nba_api`, the same library as the shots data: the all-time top 500 career scorers, then each one's season-by-season regular-season points.
- **Completeness check:** a player outside the candidate set has a career total below the smallest candidate's career total, M. So the top 10 for a season is provably complete only once that season's 10th-place cumulative total is at least M. The race starts at the first season that passes; the page names that season as the start and says why (expected around the early 1960s; the script decides, not this spec). The fetch script fails if no season passes.
- **What moves:** a bar chart race of cumulative career points, top 10, one season per step, with bars overtaking and a season counter.
- **Interaction:** play/pause and a season scrubber.

## 7. Errors

- A page whose data fails to load shows "Couldn't load the <showcase> data" with a retry button, never an empty canvas.
- Fetch scripts stop with a clear message on an unexpected column, an empty result, a failed completeness check, or a missing input file, and never write a partial file (write to a temp file, then rename).

## 8. Testing

- **Vitest:** every `lib/` module at 80% coverage or more: aggregation, scales, the race's ranking and completeness check, arc geometry, record-mode URL handling, the registry. The Worker's redirect is a pure function with its own tests.
- **pytest:** each fetch script runs against a small committed fixture, never the network. A contract test on each side checks that the Python output shape matches the TypeScript types.
- **Playwright:** every page loads and draws; the dropdown reaches every showcase; `?rec` survives navigation and yields a 9:16 frame; timelines play and scrub; the existing shots flows pass at `/shots`.
