# docs/ — specs and plans

## What this workspace is for

The design spec is the contract for the site; plans are the argument from spec to tasks. Read the spec before changing behaviour.

## Layout

```
docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md   what and why
docs/superpowers/plans/YYYY-MM-DD-<topic>.md          how, task by task
```

## Rules

- A behaviour change updates the spec in the same commit.
- Plans are historical once executed; do not edit them to match later drift, write a new one.
