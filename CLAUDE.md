# viz

A small gallery of D3 data visualisations, made for reels: a dropdown in the header switches between showcases, each a page of its own with a one-line hook, and `?rec` locks any page into a 9:16 frame for recording. Every number comes from a named public source. The live showcases are All-Star Shots (`/shots`), every US tornado since 1950 (`/tornadoes`), a year of M4.5+ earthquakes (`/quakes`), the NBA's all-time scoring race (`/scoring`) and the 1,000 busiest air routes in the lower 48, 2025 (`/flights`). Live at https://viz.jmlr.dev; https://shots.jmlr.dev redirects to `/shots`.

**Stack.** A static multi-page site (TypeScript + D3, one esbuild entry per page, shared chunks), and a Worker that redirects, sets headers and serves assets. Data is pulled on a laptop by the Python scripts under `scripts/` and committed under `public/data/<slug>/`. pnpm, Wrangler, Vitest, Playwright, pytest.

**Standing constraint.** A portfolio piece, not a revenue bet. Must not touch the Fantasy IQ season window (opens 2026-10-20).

## Naming conventions

| Workspace | Pattern | Example |
|---|---|---|
| `src/` | kebab-case files, one pure module per concern under `src/web/<slug>/lib/` | `hexes.ts`, `zone-table.ts` |
| `scripts/` | snake_case Python, one script, tests beside it | `fetch_shots.py`, `test_fetch_shots.py` |
| `public/data/` | generated only, never hand-edited | `players/203999.json` |
| `docs/` | `superpowers/specs/YYYY-MM-DD-<topic>-design.md`, `superpowers/plans/YYYY-MM-DD-<topic>.md` | `2026-09-13-allstar-shots-design.md` |

## Rules

1. **The data is what the named public source reported.** No invented, smoothed, or imported-from-elsewhere values. `public/data/` is generated by the scripts under `scripts/` and committed; never hand-edit it.
2. **The Worker never calls an outside API.** Fetching happens on a laptop, output is committed; the Worker does the host redirect, sets headers and serves files.
3. **Math is pure and tested.** Everything under `src/web/<slug>/lib/` takes data in and returns data out, no DOM, 80% coverage. DOM wiring lives in each `src/web/<slug>/index.ts` and is covered by Playwright.
4. **Constants live in each showcase's `src/web/<slug>/config.ts`** (for shots, `ZONES` also in the Python script; the index file is the contract and a test on each side checks it).
5. **Immutable data handling** in code: return new objects, never mutate inputs.
6. **Every showcase footer credits its source and states no affiliation.** The credit lives in the registry entry. Do not remove it.
7. **Headers live in `src/headers.ts`; there is no `_headers` file** (the Worker runs first, so Cloudflare would ignore it).
